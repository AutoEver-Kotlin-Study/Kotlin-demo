# 아키텍쳐


## 헥사고날 아키텍처

참고: https://github.com/thombergs/buckpal


- `port.in`: 외부에서 들어오는 요청(Controller 등).
  - `usecase`로 정의하고, 이는 서비스
  - `controller`에서 in port를 타고 서비스(비즈니스 로직) 레이어으로 접근
- `port.out`: 외부로 나가는 요청(DB 등)
- `adapter`: `port`를 구현하는 구현체

### 헥사고날을 이용한 이유

- 추후 scale out 위해 적용
  - 특히 lock의 경우 redis를 이용하는 등의 방향이 적합함
  - db 변경
  - 알림을 줄 경우, 알림 관련 회사를 이용할 수도 있고 aws 등 클라우드 내장된 기능을 이용할 수도 있음. 또한 카카오톡/이메일/fcm 등 확장될 여지가 있음.
- 확장성을 위해서 적용
  - db 가 변경되거나 이벤트를 카프카로 발행하는(~~보통 outbox 패턴을 쓸 것 같기는 하지만...~~) 등의 로직이 생기더라도 유연하게 적용 


## 시스템 아키텍처

- h2 db
- 시간 관계 상, scale out은 고려하지 않고 설계
  - 단 추후 확장성을 위해 port - adapter 구조 채택


## 이벤트 기반

- 알림은 event 기반으로 발행.
  - 알림은 이메일 / SMS 등 추가될 수 있도록 확장서 고려.
- 그룹 탈퇴 / 생성 / 참여 등 이벤트 발생
  - 이벤트에 관심이 있으면 이를 구독해서 사용.
  - `ApplicationEventPublisher` 이용.
