## 코틀린 공부 용

패키지 구조 및 아키텍처 설계 후, AI에게 구현 요청 하여 진행.

AI가 구현하면, 실제 확인하여 로직 수정하는 방향으로 진행.
- lock 에 timeout 누락 발견
- 코루틴 이용한 비동기 처리
- 팩토리 메서드 패턴 적용 등
- `SpringApplicationEventListener` 적용 요청
- swagger 적용 요청 등

AI가 구현한 것을 한 번 검토하는 방향으로 진행


## 구현 로직

docs 디렉토리 참고 부탁 드립니다.

## 느낀 점

- 당연하지만, AI를 잘 쓰기 위해서는 기본 지식이 필요
- 모든 것을 ai 맡기면, 토큰이 감당 되지 않음.
  - 토큰 절약 위해서 문제점 먼저 파악 후, 특정 파일을 어떻게 수정해줘 등 방안 필요
  - 큰 틀을 구현할 때는 플랜 모드가 좋음.(코드부터 짜면 이상하게 구현될 때 많음.)
- 비즈니스 로직 짤 때, 코틀린은 `null` 체크를 하지 않아도 되어서 너무 편함.
- 코루틴은 좀 더 적극적으로 사용해봐야 감을 잡을 것 같음.
- 회사 로직은 비즈니스 로직이 거의 존재하지 않지만, 비즈니스 로직이 좀 복잡해지면 생각해야 할 점이 많았음.
  - 사이드 프로젝트랑 달리 db 설계부터 아키텍처 정의 등 고민할 거리가 많았음
